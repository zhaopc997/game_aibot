# 项目问题与优化清单

> 审计时间：2026-10-15 · 方式：线上环境实测 + 代码静态扫描 + 数据库核对

## 一、本轮已修复（含 2 个"功能完全不可用"级 Bug）

### 🔴 1. ES 索引写入全部失败 → 攻略搜索 + AI 检索完全不可用

**现象**：搜"深渊"返回空，但数据库有 2 条匹配；AI 助手对任何问题都答
"未找到相关攻略"。

**根因**（两层）：

Spring Boot 3.3.5 的 `ElasticsearchClientConfigurations.JacksonJsonpMapperConfiguration`
内部实现是 `new JacksonJsonpMapper()` —— 用的是**裸 ObjectMapper，未注册 JSR-310**。
而 `GuideDocument.updatedAt` 是 `java.time.Instant`，于是每次写入抛：

```
InvalidDefinitionException: Java 8 date/time type `java.time.Instant` not supported by default
  (through reference chain: GuideDocument["updatedAt"])
```

**为什么长期没被发现**：`GuideIndexService.index()` 用 try/catch 吞掉异常，
`fullRebuild()` 打印的 `indexed=30` 统计的是**尝试条数**而非成功条数 ——
全部失败时日志看起来依然"成功"。

**修复**：
- 新增 `search/config/ElasticsearchClientConfig.java`，提供基于 Spring
  `ObjectMapper`（已注册 JavaTimeModule）的 `JsonpMapper` bean。
  自动配置带 `@ConditionalOnMissingBean(JsonpMapper.class)`，会正常让位。
- `fullRebuild()` 改为分别统计 attempted/succeeded，有失败时用 `log.error` 告警。

**验证**：`guides` 索引 0 → **30 条**，`updatedAt` 正确序列化为
`"2026-10-09T02:37:50.787936Z"`。

### 🔴 2. 搜索 term 查询大小写不匹配 → 即使有索引数据也搜不到

**根因**：`status` / `tags` 在索引中是 `text` 类型（standard analyzer 会**小写化**），
而查询用 `term`（**不做归一化**）传入大写枚举值 `"PUBLISHED"`。

实测（ES 直查）：

| 查询 | 命中 |
|---|---|
| `term` + `"PUBLISHED"` | **0** |
| `term` + `"published"` | 30 |
| `match` + `"PUBLISHED"` | 30 |

**修复**：改用 `.keyword` 子字段做精确匹配（`status.keyword`、`tags.keyword`）；
无关键词时改用 `matchAll`（原来传空串给 multiMatch 行为不确定）。
顺带修正 `findAllById` 返回顺序与 ES 相关性排序不一致的问题。

**验证**：搜"深渊" **2 条**（与数据库一致）、"新手" 10 条。

### 🟠 3. RAG 索引无自动重建 → 数据迁移后 AI 长期失效且重启不恢复

`IndexerService.rebuildAll()` 此前**只能**通过管理接口
`POST /api/v1/rag/reindex` 手动触发。凡是数据迁移或 ES 卷重建后，
`guide_chunks` 会一直保持 0 条，AI 助手永远答"未找到相关攻略"，
**重启也不会恢复** —— 排查时极易误判成模型问题。

**修复**：`IndexerService` 新增 `@EventListener(ApplicationReadyEvent.class)`，
启动时若索引为空而库中有攻略，自动全量重建（仅在为空时触发，不会每次重启重灌）。

**验证**：手动 reindex 后 `guide_chunks` 0 → 30 条，AI 回答变为：
> 针对你的问题「深渊平民阵容怎么打」,找到以下参考：1. 深渊平民阵容 2. 深渊满星配队 …

## 四、本轮修复的价值

两个 Bug 叠加的结果是：**搜索与 AI 助手这两个核心功能长期完全不可用，
而系统表面一切正常**（健康检查全绿、日志显示"成功"、页面无报错）。

根因都指向同一类问题 —— **失败被静默吞掉**：
- 索引写入异常被 `try/catch` 吞掉，统计口径还是"尝试数"
- 索引为空不触发任何告警，重启也不恢复

建议把"关键链路的关键指标"纳入监控（索引条数、搜索命中率），
这类问题才不会再悄悄复发。

### P0 修复命令（可直接复制执行）

**1. 修改 admin 弱密码**

密码是 BCrypt 哈希，需用应用内的 `PasswordEncoder` 生成，最简单的方式是走注册接口建新管理员、或直接替换哈希：

```bash
# 方式 A（推荐）：用强密码注册新账号，再在库里授予 ADMIN 角色
curl -X POST http://localhost:8088/api/v1/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"username":"<新管理员名>","email":"<邮箱>","password":"<强密码>"}'

# 然后授予 ADMIN（把 <用户名> 换成上面注册的）
PU=$(grep '^DB_USERNAME=' .env.production | cut -d= -f2-)
docker exec game-prod-postgres psql -U "$PU" -d guide_platform -c \
  "INSERT INTO user_role(user_id, role)
   SELECT id, 'ADMIN' FROM \"user\" WHERE username='<新管理员名>'
   ON CONFLICT DO NOTHING;"

# 方式 B：直接删除演示账号（若不需要后台）
docker exec game-prod-postgres psql -U "$PU" -d guide_platform -c \
  "DELETE FROM user_role WHERE user_id IN (SELECT id FROM \"user\" WHERE username IN ('admin','tester'));
   DELETE FROM \"user\" WHERE username IN ('admin','tester');"
```

> 改完请用新凭据验证登录，确认无误后再下线旧账号。
